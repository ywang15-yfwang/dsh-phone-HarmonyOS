# dsh 电脑端插件开发指南（方法与注意事项）

> 只讲怎么写、怎么调、哪里容易踩坑。示例里的地址、端口、路径、账号一律用占位符。

## 1. 插件由两半组成

| 半边 | 位置 | 运行环境 | 职责 |
|---|---|---|---|
| host | `lib/index.js` | dsh web 的 Node 进程 | 配对口、HTTP/WS 中转、凭据、审批状态、权限、工件、投递 |
| browser | `lib/client.js` | dsh 网页的浏览器上下文 | 补 UI（附件卡片按钮、审批点击、视频首帧） |

```json
{
  "exports": { ".": "./lib/index.js", "./client": "./lib/client.js" },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "inject": ["slots"] }
  }
}
```

host 是 Cordis 插件：导出 `name`、`inject`、`apply`。

```js
const name = "example-host";
const inject = ["webServer", "connection"];
function apply(ctx, options = {}) {
  // ctx.webServer.port = 当前 dsh 实例端口
  // options = profile 里的插件 config
}
export { apply, inject, name };
```

**注意**

- host 改动必须重启对应 dsh web；client 改动刷新网页即可。
- 同一 profile 可能被多个实例加载：用 `ctx.webServer.port` 判断“我服务的是哪一个”，端口不符就别绑配对口。
- 所有注册（路由、监听、定时器）都要返回清理函数，用 `ctx.effect` 包住，卸载/热重载才能释放。

## 2. 配对口与凭据

dsh 的 `/api` 前面有围栏：`Host` 必须回环、通常还要 cookie。手机不在本机，所以插件在**自己进程里**另开一个只对 tailnet 可见的口：

1. `/pair/info` 告诉手机：我是谁、dsh 端口、tailnet 地址、凭据绑到哪个 authority；
2. `/pair/claim` / `/pair/session` 把 dsh 的浏览器 cookie 交给手机；
3. `/pair/dsh/*` 之后把手机的 HTTP/WS 原样转给本机 dsh。

### 2.1 别自己签 cookie

```js
const auth = ctx.connection.browserAuth;              // 只在本进程有效
const url = auth.authenticatedUrl(`http://127.0.0.1:${dshPort}/`);
// 对该 url 发一次本机 GET，把 set-cookie 原样交给手机
```

`authenticatedUrl()` 用的是本进程 launch token，零漂移；自己拼签名要么复制私有算法，要么拿一个激活时才载入的活密钥去猜。

### 2.2 authority 必须与手机一致

cookie 名与签名载荷都绑 `Host`。手机若声明了别的 authority，**直接 409**，别交付一个看着能用其实 401 的 cookie。
模拟器场景（宿主回环）要显式配置 authority，不能靠猜。

### 2.3 一次性票据

- 只成功一次，重放返回明确的 `already-claimed`（410）；
- 有 TTL，过期、限速、失败都给明确错误码，不要静默重试；
- 限速按**来源 IP**，不是全局。

## 3. 需要提权时，让脚本去提，不要自己提

手机要把 SSH 公钥写进电脑（`administrators_authorized_keys` 这类位置），只有管理员能写。正确姿势：

```
POST /pair/register-key { publicKey }
  → 校验格式（ssh-ed25519 / ssh-rsa，长度上限）
  → 写临时 keyFile
  → Start-Process powershell -Verb RunAs -Wait -File <helper>.ps1 -KeyFile … -ResultFile …
  → 电脑上弹 UAC，人在电脑前点「是」
  → helper 写结果 JSON（**无 BOM**）
  → 插件轮询结果文件，返回 200 / 403
```

**注意（血泪）**

- **结果文件不能带 BOM**：`JSON.parse` 遇到 BOM 直接抛错，前端看到的就是“电脑未允许”，排查半天。
  写侧用无 BOM 的 UTF-8；读侧仍要兜一层 `replace(/^\uFEFF/, "")`。
- **UAC 子进程可能比父进程晚退出**：父进程 `exit` 后立刻读结果文件常常读不到。
  正确做法是**退出后轮询**（示例实现轮询 12 秒，250ms 一次），不要一次读失败就判失败。
- 公钥要在**提交前**做格式校验，别把垃圾内容交给提权脚本。
- helper 不存在要返回明确的 `helper-missing`（503），别让用户对着“失败”猜。

## 4. 中转：HTTP 与 WebSocket 一起转

```js
// HTTP：Host 改回环，Cookie 原样，query 原样
proxyToDsh(req, res, upstreamPath, dshPort);

// WS：升级请求不经过普通 handler，必须单独处理
server.on("upgrade", (req, socket, head) => {
  socket.on("error", () => socket.destroy());   // 必须先挂
  // 来源闸门要在这里**再判一次**
  // 再转发给 dsh
});
```

**注意**

- 裸 socket 先挂 `error`：对端在响应写出前 RST 会触发未捕获的 ECONNRESET，dsh 的 fail-loud 会直接 `process.exit(1)`。
- 升级不走 `handle()`，所以 `handle()` 里的来源校验对它**无效**，必须单独判。
- 只搬字节，不解析协议；不要试图理解 `remote.mux` 的帧。
- 转发时顺手做业务标记（例如识别 `uploadFileBinary?name=` ⇒ 这份文件是手机传的），但**不要改写请求体**。

## 5. 投递：HTTP 会撞 `writer-held`，正确解是进程内

网页端占着会话写句柄时，`session/prompt` 走 HTTP 会被 `session/writer-held` 挡掉。
插件与网页端在同一个 dsh 进程里，于是直接拿活动 agent 追加一条用户消息：

```js
const agent = ctx.get("agents").get(sessionId);
// 追加用户消息（等价于网页端键盘发出的那种），失败要有明确错误
```

**注意**

- 这是“进程内”特权，别把它当通用转发：只有 `sessionId` 明确、文本非空才做；
- 文本要截断上限（示例 8000 字符），错误分别返回 `no-injector` / `inject-failed`；
- **不要**偷偷创建会话或改用户输入。

## 6. 审批：只读状态 + 遥控网页按钮

不要在插件里抢 dsh 的 `approval/request` waterfall。让电脑网页做唯一裁决者，插件只做四件事：

1. 读会话事件 `approval/asked` / `approval/decided`，维护未决表；
2. 手机在线时通过 WS 推「未决审批」，手机回前台时 `approvals/pending` 补拉；
3. 手机点了允许/拒绝 ⇒ 通知网页脚本去点真实的「允许一次 / 拒绝」按钮；
4. 看到 `decided` 清状态并通知手机撤销。

兜底：网页没开就没有按钮可点，此时用 `/pair/desktop/open` 让电脑把网页拉起来（它是带 token 的 URL）。

**注意**

- 网页没开时，明确告诉手机“去电脑处理”，不要假装成功；
- DOM 点击是界面自动化：按**文字 + 可见性**匹配，做好失败回退；按钮文案一改就得跟着改；
- 多会话多审批时按 `sessionId + 工具名` 匹配，点错比不点更糟；
- 不要在插件里直接返回审批结果，否则会与网页重复裁决；
- 手机切后台不保证收得到，回前台补拉一次即可，不要做后台常驻通知。

## 7. 权限：只动当前会话

```js
const presets = ctx.get("permissionPresets");
const session = ctx.get("agents").get(sessionId).session;
presets.catalog();            // 可选项
presets.current(session);     // 当前值
presets.set(session, value);  // 只改这一场
```

**注意**

- 不动全局 `defaultPreset`；
- `custom` 是派生值，不能 set；
- 新建会话继承电脑默认，插件只负责“建完后改当前会话”；
- 接口要校验会话存在、值在 catalog 里，别把用户输的字符串直接塞进去。

## 8. 工件：只读 HTML

工件就是**自包含 HTML 文件**。插件只做两件事：

- 列目录：只列 `.html`，按修改时间倒序；
- 读内容：按文件名读，拒绝路径分隔符与 `..`，`content-type: text/html; charset=utf-8`。

目录必须来自**运行时配置**，不要写死在代码里。

**注意**

- 只读，不提供写/删；
- 不返回目录列表、绝对路径、隐藏文件；
- 手机用 WebView 打开，HTML 必须自包含（不能依赖外网 CSS/JS/字体）。

## 9. 手机上传：网页端要知道“这份是谁发的”

给附件卡片加按钮前，得先分清方向：手机传上来的，网页侧不该再给「保存」；反过来才给。

实现：中转 `uploadFileBinary` 时抓 `name`，记下“手机上传文件名”；网页端半边问 `/pair/phone-uploads`，
命中就不加按钮。

**注意**

- 这只是“标记”，不是鉴权；别拿它当安全边界；
- 文件名可能重名：约定取最新一条还是报歧义，写清楚；
- 标记只存内存也行（重启即清），但要接受“重启后按钮状态变了”。

## 10. browser 半边

```js
window.__ModuleLoader__.load({
  id: "example-client",
  factory: (require) => {
    const module = { exports: {} };
    exports.apply = function apply(ctx) { /* DOM 增强 */ };
    return module.exports;
  }
});
```

**注意**

- 只做增量增强，不重写宿主 DOM；用稳定的 `data-*` 钩子，别靠 class 名猜；
- `MutationObserver` 监听新增节点，操作必须**幂等**（重复扫描不能重复加按钮）；
- 不注入外部脚本/远程资源（CSP 与离线都会失败）；
- 点击、下载、打开都要有失败分支，不要 `throw` 到全局；
- **需要配对口端口时问同源的 `/pair/client-config`，不要写死**：同一 profile 可能同时跑着多个实例
  （例如 3080 和 3090），写死端口会让网页去问错实例。

## 11. 配置与多实例

```yaml
- id: pair
  config:
    port: <pair-port>        # 配对口端口
    phonePort: <dsh-port>    # 只在这个 dsh 实例上绑配对口
    credentialDays: 30
    artifactsDir: "<dir>"
```

**注意**

- 代码里只放产品默认值；地址、端口、路径、用户名一律运行时配置；
- 配置改变后 host 半边要重启 dsh web；client 只刷新页面；
- 同一端口被两个实例抢绑时，要给出明确日志，不要静默失败。

## 12. 测试清单

- `node --check lib/index.js` / `lib/client.js`；
- 单元：票据一次性、authority 不匹配、限速、401/403、格式校验；
- 监听口冒烟：**只含回环 + tailnet，绝不含 0.0.0.0**；无 tailnet 时不启动；
- WS：升级成功、对端 RST 不崩进程、半关闭能清理；
- 投递：正常追加、会话不存在、文本超长；
- 审批：前台推、回前台补拉、电脑先点手机撤销、网页没开时明确失败；
- 权限：切当前会话、重启后保持、`custom` 不可选；
- 工件：空目录、超大 HTML、非 html、`../` 攻击；
- 上传标记：手机传的能识别、桌面传的不误判；
- 重启 dsh web 后配置生效，插件卸载无残留监听/定时器。

## 13. 已经踩过的坑（照着避）

| 坑 | 现象 | 正解 |
|---|---|---|
| 结果文件带 BOM | `JSON.parse` 抛错，前端只看到“未允许” | 写侧无 BOM；读侧兜一层去 BOM |
| UAC 子进程晚于父进程退出 | 立刻读结果 → 读不到 → 误判失败 | 退出后轮询（示例 12s） |
| 裸 socket 未挂 error | 对端 RST → 进程退出 | 升级回调第一行就挂 `error` + `destroy` |
| 写死配对口端口 | 多实例时网页问错实例，按钮点了没反应 | 走 `/pair/client-config` |
| 用 HTTP 发消息 | `session/writer-held`，消息发不出去 | 进程内投递 `/pair/prompt` |
| 把浏览器里的状态当唯一事实源 | 网页刷新后状态丢，手机侧误判 | 状态以 host 侧为准，client 只做展示 |
| 在插件里自己裁决审批 | 与网页重复裁决，行为诡异 | 插件只发通知，裁决留给网页 |

## 14. 最后三条

1. **能流式就不要整包读**；能事件就不要轮询。
2. **任何 socket / stream 都要挂 error**；dsh 的进程级错误处理会把小问题放大成进程退出。
3. **代码、配置、日志、通知里都不出现个人信息**；机器相关的值一律运行时配置。
